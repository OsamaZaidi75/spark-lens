# SparkLens

**See what your Spark job actually did — from its event log, in seconds.**

Drop in a Spark event log and get the stage DAG, per-stage metrics, skew
detection, and plain-language findings. No Spark History Server, no cluster
access, no setup.

**100% client-side.** Your event log is parsed entirely in the browser and
never leaves your machine. There is no backend and nothing is uploaded.

## Features

- **Drag-and-drop upload** of `.json` and `.json.gz` event logs (gzip is
  decompressed in-browser)
- **Load sample** — try it instantly with a bundled synthetic log (2 jobs,
  6 stages, including a skewed stage, a spilling stage, and a shuffle-heavy
  stage)
- **Stage DAG** — stages as nodes with parent→child edges, colour-coded by
  health (skewed / spill / healthy)
- **Per-stage metrics table** — tasks, duration, shuffle read/write, spill
  (memory + disk), median / p95 / max task time, skew ratio
- **Skew detection** — flags stages where the slowest task runs far longer
  than the median (max/median ≥ 3×), with a per-stage task-duration histogram
- **Findings panel** — plain-language callouts: skewed stage, disk spill,
  shuffle-heavy stage, high GC time, failed tasks, longest stage
- **Header summary** — total duration, jobs, stages, tasks, shuffle moved,
  disk spill

## Try it

Live demo: https://sparklens.129-80-41-146.nip.io/

Or run locally:

```bash
npm install
npm run dev        # http://localhost:5173
```

Then click **Load sample log**, or drop in your own event log.

## How to get an event log from your Spark job

Enable event logging in your Spark config (or `spark-defaults.conf`):

```properties
spark.eventLog.enabled=true
spark.eventLog.dir=/path/to/event-logs   # local dir, S3, GCS, or ADLS
```

Spark writes one JSON-lines file per application. Download it (or its `.gz`
version) and drop it into SparkLens.

## Sample data

`public/sample-eventlog.json` is **synthetic demo data**, generated by
`scripts/generate_sample_log.py`. It is clearly labelled as sample data in the
UI. Regenerate it with:

```bash
python3 scripts/generate_sample_log.py
```

## How it works

- The parser (`src/lib/parser.ts`) reads Spark's JSON-lines event-log format:
  `SparkListenerStageSubmitted` / `StageCompleted`, `SparkListenerTaskEnd`,
  `JobStart` / `JobEnd`, `ApplicationStart` / `End`. Unknown events are
  ignored and malformed lines are counted and skipped — a bad line never kills
  the parse.
- Stage metrics are aggregated from `Task Metrics` (executor run time, GC time,
  shuffle read/write, spill, input/output).
- Skew = max task duration ÷ median task duration for completed tasks.
- Thresholds are documented constants in `src/lib/parser.ts` and
  `src/lib/findings.ts` (skew ≥ 3×, GC ≥ 10% of run time, shuffle-heavy
  ≥ 100 MB).

## Development

```bash
npm install
npm run dev        # dev server with HMR
npm test           # vitest — parser, skew math, findings, real-log fixture
npm run build      # type-check + production build into dist/
npm run demo       # Playwright end-to-end check + records demo/demo video
```

The test suite includes a fixture from a **real** Spark 3.1 event log
(`tests/fixtures/real-eventlog-excerpt.jsonl`, excerpted from the Apache Spark
repo's test resources, Apache 2.0) — see `tests/fixtures/README.md`.

## Tech

Vite + React 19 + TypeScript, no backend. DAG and histograms are hand-rolled
SVG; gzip decompression uses [pako](https://github.com/nodeca/pako). Type is
Geist Sans + JetBrains Mono, self-hosted via Fontsource.
